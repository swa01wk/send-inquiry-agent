**Spec:** [`docs/specs/demo-18nov-feedback.md`](../specs/demo-18nov-feedback.md) (gate rows NG1–NG19, stories NV01–NV11) · **Prompts:** [`prompts/demo-18nov/`](../../prompts/demo-18nov/README.md) · **Catalogue:** [`docs/flow-v2/scenarios.json`](../flow-v2/scenarios.json) (gains NV01–NV11) · **Layers:** [`docs/specs/testing-strategy.md`](../specs/testing-strategy.md), [`flow-v2-test-plan.md`](flow-v2-test-plan.md) · **Tracker:** [18 Nov demo tracker](https://claude.ai/artifact/4KmQbw2D1bwVzw7TGKTnJd), "Testing and evals"

Every change is tested on every layer that can see it, as in flow v2. Two rules are added for this round:
- Each prompt change runs the **full** `eval-live` regression, not only its new group.
- A test a change breaks is fixed **in the same PR**.

## 2. Catalogue entries NV01–NV11

The stories go into `docs/flow-v2/scenarios.json` as entries `NV01`…`NV11` (catalogue first, ADR-V6). Each backend day adds its own, in the same PR as the code. They use the same keys as S1–S24 (`steps`, `expect`, `layers`, `eval.checks`, `day`), with `changes` listing N ids. `chart_paths` is set where the story crosses chart steps (NV01, NV02, NV04, NV05, NV09) and empty otherwise.

New abstract steps (in `tests/flow_v2/steps.py` and `e2e/support/steps.ts`):

| Step | Does | Day |
| --- | --- | --- |
| `choose_option: {key, value}` | Taps the `choice` card's option (`choose_option` action) | B1 |
| `confirm_field: key` | Taps the value button of one `confirm_fields` row (`confirm_field`) | B1 |
| `verify_email: true` (changed) | Opens the verify link from the outbox (`completeVerifyLink`) through `POST /api/verifications/email`; no card button | B1 |
| `dev_clock_advance_seconds: n` | `POST /api/dev/clock/advance {hours: n / 3600}` (existing endpoint; `hours` is a float) | B2 |
| `resend_code: true` | Taps Resend on the verification card | B2 |
| `skip_email: true` | Marker: the story doesn't open the email link | B2 |
| `mark_flexible` | Typed ("flexible") in live runs; the scripted model calls the tool | B3 |
| `track: {reference, email}`, `track_code: true` | Fills the Track page; reads the code from the outbox (`track_code` template) and enters it | B4 |
| `case_comment: {doc_type?, text}`, `follow_up: text` | Per-item comment; "Send a follow-up" | B4 |
| `contacts_same_as_primary: role` | Taps "Same as primary contact" on the contacts card | B4 |

The scripted model scripts are `backend/tests/e2e_scripts/flow-v2-nv01.json` … `flow-v2-nv11.json`. They're generated by `scripts/generate_e2e_scripts.py --flow-v2` from the catalogue steps where the model speaks; B1 extends `scripts/flow_v2_e2e_compile.py` to NV entries.

## 6. AGENT-LIVE: the seven new groups

`scripts/eval_live.py`. `GROUP=nov18` runs all seven (`select_group`, PR #115). Each group's scenarios run in English and Arabic, ×3, and pass at 3/3. Checks are deterministic (state, cards, regex); none uses a model to judge. Check functions live in `app/agent/eval_checks.py` with unit tests in `tests/flow_v2/test_eval_checks.py`; Claude adds the scenarios and checks in each backend PR, and Swaroop runs and tunes them in his Cursor PR.

| Group | Scenarios (EN and AR each) | Checks |
| --- | --- | --- |
| `category_options` (B1) | "We sell coffee and breakfast"; "clothes" (broad); brand only ("Max"); Office "we do accounting" | `category_set_by_choice_only` (no derived `sales_category` write; the write comes from `choose_option` or an exact typed name); `options_from_master_data` (1–4, all known ids); `broad_answer_offers_group` (the retail categories); `never_infers_category_from_brand_alone`; `no_looks_right_wording`; `options_in_chat_language` (`lang: ar` in the Arabic run) |

**Regression.** After every Cursor PR that touches a prompt (B1–B4) and in B5: the full `make eval-live`. No existing group may fall below its last result in `docs/eval-notes.md` beyond `EVAL_TOLERANCE`. Record the run in `docs/eval-notes.md` (date, model, group results).

**KPI.** `questions_per_section`: `unit_and_category` ≤ 2, `basic_info` ≤ 3, as before. `property_details` goes up to about one question per item (N10); that's expected and noted in `eval-notes.md`.
